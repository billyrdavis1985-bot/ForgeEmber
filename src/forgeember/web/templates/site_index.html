ForgeEmber

ForgeEmber screens every email, invoice, receipt photo and voicemail a small business receives, using Muse Ember, for a fraction of a cent each. It turns messy input into verified, routed actions and holds anything risky (payments, bank-detail changes) for a person. Ember proposes; code decides.

This is a keyless replay of recorded runs: nothing here calls a model. Every number links back to the committed trace.

How it works

1 · Code looks firstLookalike domains, executive impersonation, diverted replies, prompt injection, file-type tricks. No model call.
2 · Ember proposesA coordinator triages every item at minimal effort. Only when needed, specialists read invoices and receipt photos, listen to voicemails, and look vendors up through a read-only tool. Every claim quotes the source.
3 · Code verifiesQuotes must exist verbatim, totals must add up, IBANs must pass checksum and match the vendor's account on file, and a vendor Ember names must come from a real lookup. A recording is a claim, never proof.
4 · Policy decidesFiling is automatic; payments and bank-detail changes are always held for a person. A model can raise risk, never lower it.
